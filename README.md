# Daily News Digest

하루에 필요한 뉴스만 최대 20개로 추려 매일 발행하는 뉴스 큐레이션 파이프라인입니다.
RSS 수집부터 본문 파싱, 중복 제거, 중요도 스코어링, LLM 요약, 출력 검증까지 전 과정을 자동화했고,
GitHub Actions 크론으로 격일 발행하며 결과를 정적 JSON으로 내보냅니다.

- 프론트엔드: [daily-digest](https://github.com/CEJSH/daily-digest) · [데모](https://daily-digest-eta.vercel.app)
- 발행 데이터: [`data/daily_digest.json`](data/daily_digest.json) · [`data/archive/`](data/archive)

---

## 왜 만들었나

뉴스 서비스 대부분은 더 많이 보여주는 방향으로 최적화되어 있습니다. 클릭을 유도하는 헤드라인, 체류 시간을 늘리는 추천, 읽고 나면 남는 게 없는 단발성 소식이 섞여 있습니다.

이 프로젝트는 반대 방향을 택했습니다. **내일도 영향이 남는 이슈만, 하루 20건 이하로, 감정 소모 없이** 정리하는 것이 목표입니다. 아래의 스코어링·필터링 규칙은 전부 이 기준을 코드로 옮긴 것입니다.

**선정 기준**

1. 내일도 영향이 남는 구조적 이슈 (정책·규제 변화, 산업 파급력)
2. 감정 소모를 유발하지 않는 정보 - 단순 화제성은 감점
3. 이전 발행 호와 중복되지 않는 내용

연예·가십·사건사고는 수집 단계에서 제외합니다.

## 파이프라인

```
RSS 수집 → 본문 파싱 → 중복 제거 → 중요도 스코어링 → 상위 20건 선별
        → LLM 요약·보강 → 출력 검증 → JSON 발행 → 프론트엔드 반영
```

| 단계 | 모듈 | 하는 일 |
|---|---|---|
| 수집·파싱 | `scrapers/article_fetcher.py` | 공개 RSS 피드에서 기사 수집, 본문 추출 |
| 중복 제거 | `processing/dedupe.py` | 클러스터 키 생성, 표층·의미 기반 중복 판정 |
| 스코어링 | `processing/scoring.py` | 구조적 신호 기반 중요도 산출, 소스 다양성 강제 |
| 요약·보강 | `processing/ai_service.py`, `ai_enricher.py` | Gemini API로 3줄 요약, 중요성 설명, 영향 신호 추출 |
| 검증 | `export/validators/` | 근거(evidence)·영향 신호(impact signal) 정합성 검사 |
| 발행 | `export/export_manager.py` | JSON 직렬화, 아카이브 인덱스 갱신 |

각 기사는 3줄 요약, "왜 중요한가" 한 문장, 중요도 점수, 영향 신호(정책·실적·수요 등), 예상 읽기 시간, 원문 링크를 포함합니다.

## 설계하면서 다룬 문제들

이 파이프라인에서 시간을 가장 많이 쓴 곳은 수집이나 요약이 아니라 **중복 판정과 오탐 억제**였습니다.

**중복 판정의 정확도**

같은 사건을 다룬 기사들이 매체마다 다른 제목을 달고 들어옵니다. 단순 문자열 비교로는 잡히지 않고, 반대로 느슨하게 잡으면 서로 다른 사건이 하나로 묶입니다. 클러스터 키를 생성할 때 불용어·어미·날짜·범용어를 제거해 정규화하고, 표층 중복과 의미 기반 중복을 분리해 처리했습니다. 엔티티·도메인이 겹친다는 이유만으로 묶이던 오탐도 조건을 재조정해 완화했습니다. 중복 이력은 `data/dedupe_history.json`에 누적해 이전 발행 호와의 중복까지 검사합니다.

**본문 오인 추출**

일부 매체는 RSS 링크가 기사 본문이 아니라 목록형 페이지로 연결됩니다. 그대로 파싱하면 기사 제목 나열이 본문으로 들어옵니다. 목록형 페이지 패턴을 판별해 제외하고, 본문 최소 길이 기준과 드롭 사유 로깅을 함께 두어 어떤 기사가 왜 탈락했는지 추적할 수 있게 했습니다.

**LLM 출력의 신뢰성**

요약과 영향 신호는 LLM이 생성하므로 값이 비거나 근거 없이 채워질 수 있습니다. `evidence`, `impact_signal` 검증기를 두어 근거 없는 항목이 조용히 통과하지 않게 했고, 중요도 점수와 영향 신호가 서로 모순되는 경우를 강제로 정합화합니다. 빈 값은 재시도·자동 보정 경로를 따릅니다.

**후보 부족 상황 처리**

신뢰 소스 allowlist를 엄격히 적용하면 발행 기준 개수를 못 채우는 날이 생깁니다. allowlist 후보가 상한에 미달할 때만 신규 후보로 보충하는 완화 로직을 넣고, 해당 경로에 회귀 테스트를 붙였습니다.

이런 판정 로직은 한 번 고치면 다른 곳이 틀어지기 쉬워서, 수정할 때마다 회귀 테스트를 함께 추가하는 방식으로 작업했습니다.

## 프로젝트 구조

```
src/daily_news_digest/
  core/           설정, 상수
  scrapers/       RSS 수집, 본문 추출
  processing/     중복 제거, 스코어링, LLM 요약·보강, 파이프라인
    prompts/      요약 프롬프트
  export/         JSON 직렬화, 아카이브 인덱스
    validators/   근거·영향 신호 검증
  models/         도메인 모델
  utils/
tests/            pytest 기반 회귀 테스트
.github/workflows/build-digest.yml   격일 자동 발행 크론
data/
  daily_digest.json    최신 호
  index.json           아카이브 목차
  archive/             날짜별 스냅샷
```

## 실행

```bash
pip install -r requirements.txt
cp config/.env.template config/.env   # API 키 설정
python -m daily_news_digest
```

```bash
pytest
```

## 자동화

GitHub Actions가 격일로 파이프라인을 실행해 `data/` 하위 JSON을 갱신하고 커밋합니다. 프론트엔드는 이 JSON을 런타임에 가져와 렌더링하므로, 별도 서버 없이 운영 비용이 발생하지 않습니다.
